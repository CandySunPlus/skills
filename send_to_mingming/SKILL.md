# 把待确认的问题发给时明明

## 发送问题

1. 从当前访谈中找出用户交给时明明的问题，保留原题号和顺序。用户可以一边回答其他题，一边指定要转问的题，例如「Q1 可以，Q3 和 Q5 帮我问时明明」。先记下用户已经给出的答案。单说「不确定」时，继续原访谈。若调用技能时没说清要转问哪些题，且上下文也无法确定，只问缺少的题号。
2. 把选中的题合成一条中文私信。开头用一两句交代正在讨论什么、请时明明确认什么。每题保留编号，写出具体的判断点和理解问题所需的前提，必要时附上选项、当前倾向及理由。把已知情况与待确认的建议写清楚，方便对方按编号回复。只带上理解这些题所需的上下文。
3. 用户明确让你发送这些题，或带着题号调用本技能时，以用户身份调用飞书 SDK。通过 `uv run --script <技能目录>/scripts/feishu.py send --uuid <本批次的 UUID>` 发送，从标准输入传入正文。用户只要草稿时，在当前聊天给出文案。
4. 收到飞书回执后报告已发送的题号，将题号与回执的 `message_id`、`chat_id`、`sent_at_ms` 一起保留在访谈上下文，标记为「等时明明回复」。继续询问能独立推进的题。发送失败时说明原因并给出完整文案。缺少授权时读取[飞书配置说明](references/feishu-setup.md)并说明缺哪一步。发送状态不明时先核对会话。同一批次确需重试时使用原 UUID。

## 查看回复

用户要求查看回复时，用该批回执执行 `uv run --script <技能目录>/scripts/feishu.py replies --chat-id <chat_id> --after-ms <sent_at_ms>`。脚本仅返回已配置收件人在该时间之后发送的消息。用引用关系、题号和内容判断答复对应的问题，其余题保持待确认。用户转述答复时也按原题号接回访谈，沿用 `grill-with-docs` 对已确认决定的记录规则。

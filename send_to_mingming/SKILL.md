# 把待确认的问题发给时明明

## 发送问题

用户用「跟明明说」等说法直接交代要转达的正文时，把指定正文作为待预览的文案。遇到引用、举例或讨论这些说法时，按用户实际请求处理。

1. 从当前访谈中找出用户交给时明明的问题，保留原题号和顺序。用户可以一边回答其他题，一边指定要转问的题，例如「Q1 可以，Q3 和 Q5 帮我问明明」。先记下用户已经给出的答案。单说「不确定」时，继续原访谈。若要转达的题号或正文无法从上下文确定，只问缺失的信息。
2. 把选中的题合成一条中文群消息。开头用一两句交代正在讨论什么、请时明明确认什么。每题保留编号，写出具体的判断点和理解问题所需的前提，必要时附上选项、当前倾向及理由。请时明明引用这条群消息并按题号回复。
3. 在当前 Codex 聊天展示完整正文，注明将由飞书机器人发到已绑定的群，并等待用户明确确认这版文案。每次发送都要经过预览和确认，包括用户直接提供正文或指定题号的情况。用户只要草稿时，展示草稿即可。用户修改正文或调整题目时，展示新的完整文案并再次等待确认。
4. 收到用户对当前预览的明确发送确认后，通过 `uv run --script <技能目录>/scripts/feishu.py send --uuid <本批次的 UUID>` 发送，从标准输入原样传入已确认的正文。将访谈中的答题或对方案的同意按原意记下，发送确认必须指向预览的文案。
5. 收到飞书回执后报告已发送的题号，将题号与回执的 `message_id`、`chat_id`、`sent_at_ms` 一起保留在访谈上下文，标记为「等时明明回复」。继续询问能独立推进的题。发送失败时说明原因并给出完整文案。群尚未绑定或应用权限有误时，查看[飞书配置说明](references/feishu-setup.md)。发送状态不明时先核对目标群，同一批次确需重试时使用原 UUID。

## 查看回复

用户要求查看回复时，用该批回执执行 `uv run --script <技能目录>/scripts/feishu.py replies --chat-id <chat_id> --after-ms <sent_at_ms>`。脚本仅返回已配置收件人在该时间之后发送的消息。用引用关系、题号和内容判断答复对应的问题，其余题保持待确认。用户转述答复时也按原题号接回访谈，沿用 `grill-with-docs` 对已确认决定的记录规则。

# 把待确认的问题发给时明明

1. 从当前访谈中找出用户交给时明明的问题，保留原题号和顺序。用户可以一边回答其他题，一边指定要转问的题，例如「Q1 可以，Q3 和 Q5 帮我问时明明」。先记下用户已经给出的答案。单说「不确定」时，继续原访谈。若调用技能时没说清要转问哪些题，且上下文也无法确定，只问缺少的题号。
2. 把选中的题合成一条中文私信。开头用一两句交代正在讨论什么、请时明明确认什么。每题保留编号，写出具体的判断点和理解问题所需的前提，必要时附上选项、当前倾向及理由。把已知情况与待确认的建议写清楚，方便对方按编号回复。只带上理解这些题所需的上下文。
3. 用户明确让你发送这些题，或带着题号调用本技能时，直接发送。用户只要草稿时，在当前聊天给出文案。优先使用已连接且支持联系人查找和私信的飞书工具。本机可用飞书桌面客户端时，读取并使用 `cua-driver` 技能操作飞书（macOS 应用可能叫 `Lark.app`）。打开搜索后，如果弹窗有独立窗口 ID，以弹窗作为搜索输入的目标。在搜索结果中找到「时明明」，优先定位已有的一对一会话，核对收件人后再发送。遇到同名且无法确认，先向用户索取能区分联系人的信息。
4. 从飞书的发送结果或目标会话里出现的新消息确认发送成功，再向用户回报题号。发送结果不明时先检查会话，确认前避免重发。如果没有可用的发送方式，或发送失败，说明状态并贴出可复制的完整文案。
5. 在访谈中将已发题保留为「等时明明回复」，未发题标为「待发送」。继续询问当前能独立推进的问题，依赖这些答复的题留到收到回复后再问。用户转述答复或要求查看飞书回复时，按原题号接回访谈。把建议和已确认的决定区分开，沿用 `grill-with-docs` 对已确认决定的记录规则。

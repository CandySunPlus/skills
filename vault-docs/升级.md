# 把已装好的仓库升级到 skill 的当前版本

用在：这个仓库已经装了镜像机制，而 skill 那边的脚本或模板往前走了。脚本是复制进去
的、不是软链，所以不会自己跟上。

## 一、先看差了什么

```bash
SKILL=~/.claude/skills/vault-docs
for f in mirror-common.sh sync-docs.sh check-docs-mirror.sh rewrite_wikilinks.py; do
  cmp -s "$SKILL/scripts/$f" "scripts/$f" || echo "差异：$f"
done
```

配置不能这么比——`.mirror.conf` 里是本项目的取值，与模板逐字不同是正常的。要看的是
**结构**：模板里多出或去掉了哪个键。

```bash
diff <(grep -o '^[A-Z_]*=' "$SKILL/templates/mirror.conf" | sort) \
     <(grep -o '^[A-Z_]*=' .mirror.conf | sort)
```

## 二、拷脚本

四个是一组，整组拷比逐个挑省事：

```bash
cp "$SKILL"/scripts/*.sh "$SKILL"/scripts/rewrite_wikilinks.py scripts/
chmod +x scripts/*.sh scripts/rewrite_wikilinks.py
```

**脚本之外还有东西要跟着改，而 `cmp` 看不出来。** 逐条对 `安装.md`：配置里的键、
`.gitignore` 的条目、横幅模板、CI workflow 的 `paths` 列表。上一节那条 `diff` 只盖住
配置的键，其余几处得照着 `安装.md` 过一遍。

## 三、重跑同步

命令与日常改文档同一套，见 `SKILL.md` 的「改文档」。

**升级后第一次同步会打出一批与任何文档改动无关的差异**：脚本改了产出的形态，全仓库
跟着变。这批要**单独提交**，别混进手上正在做的文档改动——混了之后没人分得出哪一行是
内容改的、哪一行是脚本改的。

同步输出里两栏要读：

- **`锚点译不出来 N 处`** —— 逐条列着。块引用 `#^块号` 在 GitHub 上没有对应锚点，
  落文件顶部是终态；对不上任何标题的那些是 vault 侧的真错（那一节改名或删了），去改。
- **`git status --short`** —— 出现 `D` 就停下来确认那是有意的，别顺手连着提交。

## 四、镜像与基线同提交

漏了基线，别人和 CI 会报「内容被修改」。

## 红旗

- **只拷脚本、不重跑同步。** 此刻校验全绿——镜像与基线都是旧的、彼此一致，看不出升级
  没生效。代价推给了下一个人：他做一句话的文档改动，那批链接变化会连着他的提交一起进去
- 拿 `templates/mirror.conf` 直接覆盖 `.mirror.conf`，把本项目的取值抹掉
- 拷了脚本却没给可执行位
- 看到「锚点译不出来」那一栏不管它
